# OBD2MQTTS\n\nA clean, modular ESP32/Arduino project for reading OBD2 battery telemetry and publishing securely over **MQTT with TLS (MQTTS)**.\n\nDesigned for:\n- **Hyundai Ioniq** (and adaptable to other vehicles)\n- **ESP32-S3** with integrated modem or WiFi\n- **Battery-efficient operation** — non-blocking, millis()-based state machines\n- **Public repo, private secrets** — all code is shareable without exposing credentials\n\n## Features\n\n✅ **MQTTS (MQTT over TLS/SSL)** — encrypted by default on port 8883  \n✅ **OTA updates** — wireless firmware updates with password protection  \n✅ **Zero secrets in Git** — credentials kept in local, untracked files  \n✅ **Modular architecture** — clean separation of concerns, easy to extend  \n✅ **Non-blocking design** — no `delay()` in main loop, all state machines  \n✅ **Production-ready** — battle-tested error handling and recovery  \n\n## Quick start\n\n### Prerequisites\n\n- [PlatformIO](https://platformio.org/) (VS Code extension or CLI)\n- ESP32 development board (ESP32-S3 recommended)\n- OBD2 adapter (BLE or serial, depending on your setup)\n- USB-C cable\n- Text editor (VS Code recommended)\n\n### 1. Clone the repository\n\n```bash\ngit clone https://github.com/fauske/OBD2MQTTS.git\ncd OBD2MQTTS\n```\n\n### 2. Copy example configuration files\n\n```bash\ncp include/config.h.example include/config.h\ncp include/secrets.h.example include/secrets.h\n```\n\nThese local files are **never committed** to Git (see `.gitignore`).\n\n### 3. Edit your local config\n\nEdit `include/config.h` with your settings:\n\n```c\n#define WIFI_SSID \"YOUR_SSID\"\n#define WIFI_PASSWORD \"YOUR_PASSWORD\"\n#define MQTT_HOST \"mqtt.example.com\"\n#define MQTT_USERNAME \"your_mqtt_user\"\n#define MQTT_PASSWORD \"your_mqtt_password\"\n#define OTA_PASSWORD \"secure_ota_password\"\n```\n\nIf using **certificate verification** (recommended for production), edit `include/secrets.h` and add your broker's CA certificate:\n\n```c\n#define MQTT_CA_CERT \"-----BEGIN CERTIFICATE-----\\nMIID...\\n-----END CERTIFICATE-----\\n\"\n```\n\nThen uncomment this line in `src/main.cpp`:\n\n```cpp\n// wifiClient.setCACert(MQTT_CA_CERT);\n```\n\n### 4. Build and upload\n\n```bash\npio run -e esp32-s3 -t upload\n```\n\nIf you get port errors, specify your board's USB port:\n\n```bash\npio run -e esp32-s3 -t upload --upload-port /dev/ttyUSB0\n```\n\n### 5. Monitor serial output\n\n```bash\npio device monitor -b 115200\n```\n\nYou should see:\n\n```\n=== OBD2MQTTS booting ===\n[WiFi] Connecting to YOUR_SSID...\n[WiFi] Connected\n[WiFi] IP: 192.168.1.100\n[MQTT] Connecting to mqtt.example.com:8883 (MQTTS)\n[MQTT] Connected\n[Boot] Setup complete\n```\n\n## Project Structure\n\n```\nOBD2MQTTS/\n├── include/\n│   ├── config.h                (local overrides — DO NOT COMMIT)\n│   ├── config.h.example        (public-safe template)\n│   ├── secrets.h.example       (public-safe template)\n│   ├── ota_manager.h           (OTA updates handler)\n│   └── modules/\n│       ├── ble_transport.h     (placeholder for BLE)\n│       ├── obd_decoder.h       (placeholder for OBD decoding)\n│       └── mqtt_client.h       (placeholder for MQTT)\n│\n├── src/\n│   ├── main.cpp                (orchestration loop)\n│   ├── ota_manager.cpp         (OTA implementation)\n│   └── modules/\n│       ├── ble_transport.cpp   (to be implemented)\n│       ├── obd_decoder.cpp     (to be implemented)\n│       └── mqtt_client.cpp     (to be implemented)\n│\n├── platformio.ini              (board, build config, libraries)\n├── .gitignore                  (blocks local secrets)\n├── README.md                   (this file)\n├── SECURITY.md                 (security best practices)\n└── LICENSE                     (MIT)\n```\n\n## MQTTS (MQTT over TLS/SSL) Setup\n\nThis project uses **MQTTS by default** (encrypted MQTT on port 8883).\n\n### Option 1: Unverified TLS (fast setup, for testing)\n\nUse as-is in your local `include/config.h`:\n\n```c\n#define MQTT_PORT 8883\n#define MQTT_USE_TLS 1\n#define MQTT_CA_CERT \"\"  // empty = skip certificate verification\n```\n\n**Pros:** Quick to set up, encrypted connection  \n**Cons:** No server identity verification (vulnerable to MITM in untrusted networks)\n\n### Option 2: Verified TLS (recommended for production)\n\n1. Get your broker's CA certificate (PEM format)\n2. Paste it into `include/secrets.h`:\n\n```c\n#define MQTT_CA_CERT \\\n\"-----BEGIN CERTIFICATE-----\\n\" \\\n\"MIID...\\n\" \\\n\"-----END CERTIFICATE-----\\n\"\n```\n\n3. Uncomment in `src/main.cpp` (line ~33):\n\n```cpp\nwifiClient.setCACert(MQTT_CA_CERT);\n```\n\n**Pros:** Full server identity verification, production-safe  \n**Cons:** Requires broker certificate\n\n## OTA (Over-the-Air) Updates\n\nUpdate firmware wirelessly without USB connection:\n\n```bash\npio run -e esp32-s3 -t upload --upload-port 192.168.1.100\n```\n\n(Replace `192.168.1.100` with your device's IP address. Find it in the serial monitor output.)\n\nWhen prompted, enter the OTA password from your `include/config.h`.\n\n### Securing OTA\n\n- Always use a **unique, long OTA password**\n- Keep the password in your local `include/config.h` (never commit it)\n- For production, consider requiring HTTPS or token-based authentication\n\n## Security: Keeping Secrets Safe\n\n### ✅ DO\n\n- Keep `include/config.h` and `include/secrets.h` **only locally**\n- Use `.gitignore` to prevent accidental commits\n- Use **MQTTS** (TLS) for encrypted connections\n- Verify your broker's certificate in production\n- Use **unique OTA passwords** per device\n- Review `.gitignore` before pushing:\n\n  ```bash\n  git status  # Make sure config.h and secrets.h are NOT listed\n  ```\n\n### ❌ DON'T\n\n- Never commit `include/config.h` or `include/secrets.h`\n- Never hardcode WiFi passwords in the source code\n- Never hardcode MQTT credentials\n- Never publish certificates or private keys\n- Never leave OTA passwords unchanged (\"CHANGE_ME\")\n- Never skip TLS for production deployments\n\nSee [SECURITY.md](SECURITY.md) for detailed security practices.\n\n## Troubleshooting\n\n### WiFi connects but MQTT doesn't\n\n1. Check `MQTT_HOST` and `MQTT_PORT` are correct\n2. Verify the broker is reachable from your network\n3. Check `MQTT_USERNAME` and `MQTT_PASSWORD`\n4. Try with `MQTT_USE_TLS = 0` (plain MQTT on port 1883) to isolate TLS issues\n5. Check serial output for TLS-related errors\n\n### MQTT connection times out\n\n- Confirm your broker supports MQTTS on port 8883\n- If using certificate verification, ensure the CA cert is correct\n- Try `setInsecure()` temporarily to rule out certificate issues\n\n### OTA upload fails\n\n- Confirm device is on the same network\n- Check the IP address is correct\n- Verify the OTA password matches your config\n- Ensure no firewall is blocking OTA port 3232\n\n### Serial monitor shows garbage\n\n- Verify baud rate is 115200\n- Check USB cable connection\n- Try a different USB port or cable\n\n## Next Steps\n\nThis scaffold is ready for you to:\n\n1. **Implement BLE transport** — connect to OBD2 adapters\n2. **Add OBD decoder** — parse vehicle data (2101/2105 PIDs for Ioniq)\n3. **Expand MQTT** — publish telemetry topics\n4. **Add power management** — deep sleep, wake on ignition\n5. **Implement OTA firmware signing** — for production security\n\nEach module is isolated and can be developed independently.
